# AGENTS.md — working on pide

pide is a personal native code editor in Rust on GPUI + GPUI Kit, with the pi coding agent built in.
The spec is the claude.ai doc "pi IDE — Implementation Spec" (https://claude.ai/artifact/ES6XEPGZHMPVQ6cWXYMLPE).
Milestones run in order (M0–M6). Since 2026-11-10 the user doesn't need to sign off each one: keep going, test in the app, and report progress (see the progress artifact in memory).
Primary target: macOS on Apple Silicon. Linux is secondary.

## Crate layout

## Rules (from the spec — they exist because this is where agents go wrong)

1. **Current GPUI API only:** `Entity<T>`, `Context<T>`, `Window`, `App`. `View`, `ViewContext`, `WindowContext`, `Model` don't exist anymore.
2. **Copy from `reference/` at the pinned version.** Don't write GPUI from memory. Import GPUI only via `gpui_kit` — never add a `gpui`/`gpui-pre` dependency.
3. **`cargo check` after every file you change.** Never leave the workspace not building.
4. **Don't write editing code** (buffer, cursor, rendering, highlighter). If GPUI Kit's editor can't do something, write it in `docs/GAPS.md` and ask the user.
5. **Don't guess pi's protocol.** pi logs every raw line to `~/.local/state/pide/pi-rpc.jsonl`; derive types from what's there. Tests use recorded fixtures (`crates/agent-pi/tests/fixtures/`). Read the installed pi's `docs/rpc*.md` and `docs/json.md` (`$(npm root -g)/@earendil-works/pi-coding-agent/docs`).
6. **No highlighting = a missing tree-sitter Cargo feature**, not a bug. Features are set once, in the workspace `Cargo.toml`. Languages GPUI Kit has no grammar for at all are registered at startup with `LanguageRegistry::register` and our own highlight query (LaTeX: `editor/src/latex.rs`, grammar crate `codebook-tree-sitter-latex`; `tree-sitter` must stay the version GPUI Kit uses). Test a query with a unit test (it must compile against the grammar).
7. **Panels never import each other.** Shared needs go into `core` as an event or command — ask the user first. (Example: the file tree opens files through the `FileOpener` global the app installs, not by depending on `pide-editor`.)
8. **Keep scope to the current milestone.** Ideas go in `docs/IDEAS.md`.
9. **Keep this file up to date.**
10. **Commits:** small, one per working step, clear messages. **No AI attribution anywhere** — no `Co-Authored-By`, no session links, no "Generated with".

## Conventions and gotchas learned so far

- **No I/O on the UI thread.** File reads/writes go through `cx.background_executor()`; pi and (later) LSP I/O run on the tokio runtime (`pide_runtime::spawn`) and come back over `tokio::sync::mpsc` into a `cx.spawn` task. Exceptions, on purpose: the saved layout (a few KB) is read once at startup.
- **Re-entrancy:** `AgentBackend` methods run inside the `Agent`'s own update. Use the `&mut Agent` argument; calling `cx.entity().update(..)`/`.read(..)` on it there panics.
- **Panels reach each other only through `core`:** `opener::open_file` / `open_diff` (installed by the app), `context::current(window, cx)` (installed by the editor), `Services { workspace, sessions }`.
- **One window per project (M2.5).** `Services` is per window, not a global: get it with `Services::of(window, cx)` (in a panel's `new`, then keep the handles in fields). Anything else that is per project (editor dock host, open-tab lists, the shell) is keyed by `WindowId` and dropped in the app's `on_window_closed`. Never add a project-wide `Global`.
- **One `Agent` per session.** `Sessions` holds them; `Services::active_agent(window, cx)` is the one the pi panel shows. New `AgentEvent`s go in `core/src/events.rs`, parsing in `agent-pi/src/wire.rs`, with a recorded fixture test.
- **Testing pi config changes** without touching the user's: `PI_CODING_AGENT_DIR=<copy of ~/.pi/agent>` (pi and pide both honour it).
- **Driving the app in tests, without touching the user's screen:** `cargo build -p pide --features devctl`, then `PIDE_CTL=/tmp/pide-<you>.sock dev/pidectl launch <project>`. The window stays hidden and the app never activates. `dev/pidectl run <command> | keys "cmd-9 down" | type … | click X Y [right] | scroll X Y DY | shot out.png --scale 0.5 | quit` (`crates/app/src/devctl.rs`). Shots are rendered by GPUI itself (`render_to_image`), never a screen capture, so they never show the user's other windows. Coordinates are window points; shots are 2× pixels. Unix socket paths must be short (< 104 bytes): use `/tmp`. The `devctl` feature needs gpui-kit's `test-support`, which is why `unicode-properties` is pinned to 0.1.3 in `Cargo.lock` (gpui-fast-web wants exactly that). Don't use real clicks/keystrokes or `screencapture` on the user's machine.
- **Don't test pide on this repo with rust-analyzer running for long:** its `cargo check` writes to `target/` and the disk is nearly full. Use a small demo project.
- **Git:** read with `gix`, write with the `git` CLI (`panels/git/src/repo.rs`). Keep `gix` features minimal (`status`, `sha1`, `parallel`; no network) — the disk is tight.
- **Git gutter** (`core/src/git.rs`): branch from `.git/HEAD`, HEAD text via `git show`, line diff with `similar`; the editor draws marks with GPUI Kit's gutter decorations (`editor/src/git_gutter.rs`).
- **Collaborator mode** (docs/COLLAB.md): pi talks to pide through its own extension's tool results (`details: {pide: 1, kind, …}` in `tool_execution_end`), not a side channel. A new pide tool = a `registerTool` in `crates/agent-pi/ext/pide.ts` (plain JSON Schema, no imports beyond node built-ins), a `kind` in `wire::collab_event`, an `AgentEvent`, and a fixture. Pins and notes are anchored by line + the line's text (`collab::Anchor`); re-find by text, never trust the line alone. Panels walk through stops only via `pide_core::collab` (it opens the file and marks the stop seen).
- **Dev hooks:** `PIDE_PI_ARGS` adds flags to every pi process (`PIDE_PI_ARGS="-e dev/pi-ask-test.ts"` loads the dialog test extension: send `/ask-test`). `PIDE_BENCH=<file>` runs the frame benchmark.
- **Never read an entity inside its own update.** GPUI panics (“cannot read X while it is already being updated”) and, inside a macOS event callback, aborts the app. It has bitten four times: a command run from the shell's listener, a tab switch from inside the panel, a GPUI Kit provider (`perform_code_action` runs inside the editor's update), and a palette that opens a window. Run commands from a plain `on_action` (not `cx.listener`), `cx.defer`/`window.defer` work that touches the caller, and don't read the `EditorState` passed to a provider callback.
- **Editor-only keys** use `CommandSpec::in_context(pide_core::commands::EDITOR)`; a global key shadows the same key in narrower contexts (Alt+Enter in the pi composer).
- **Every action is a command.** Register with `CommandRegistry::register(cx, CommandSpec::new("area.verb", "Title").key("cmd-…"), handler)`. Keys are JetBrains-style macOS defaults. Keybindings all dispatch `RunCommand { id }`, handled by the shell's root view.
- **Completion extras:** GPUI Kit applies only a completion's main edit. `Providers` keeps the last list (shown and raw); the editor panel spots the accepted item in `InputEditsEvent` and applies its `additionalTextEdits`, resolving the item first when needed (rust-analyzer's auto-import items carry `data` but don't report `resolveProvider`).
- **LSP positions:** everything to or from a server goes through `pide_lsp::convert` (characters ↔ the server's encoding). Never hand a server range to GPUI Kit unconverted.
- **LSP store:** `LspStore::for_workspace(&workspace, cx)`; it lives as long as the workspace, and dropping it kills its servers. Logs: `lsp-rpc.jsonl`, `lsp-<server>-stderr.log`.
- **Keymap hot reload** snapshots GPUI Kit's own bindings once (`keymap::init`, after every crate's `init`) and re-adds them on each reload — so call `keymap::init` last.
- **Tool windows:** a side/bottom panel registers a `ToolWindowSpec` in its crate's `init` (id = `panel_name`, icon, home dock, toggle command + key, `create`). Don't add per-panel show/toggle code to the shell; `pide_core::toolwindow::toggle(id, …)` shows (creating it in its home dock the first time), focuses, or hides it. Where a tool sits after Move to… lives in the saved dock layout.
- **Panel trait:** ours is `pide_core::Panel` (`title_text`, `default_dock`) on top of GPUI Kit's dock `Panel`/`BasePanel` (`panel_name`, `title`, `dump`). It's `title_text`, not `title`, because GPUI Kit already has a `title` method.
- **Saved layouts** rebuild panels by `panel_name` through `register_panel`; a panel that needs state (an editor's path) writes it in `dump()` as `PanelInfo::panel(json)`. Bump `DOCK_VERSION` in `app/src/shell.rs` when the default layout changes incompatibly.
- **`use gpui_kit::*` shadows `#[test]`** with GPUI's test macro. In test modules that glob-import it, write `#[::core::prelude::v1::test]`.
- **Outside changes are undoable:** a reload (pi's edit, another program) or `Workspace::replace_text` reaches the editor through `minimal::set_text` (line edits via `apply_lsp_edits`), never `set_value`, which wipes undo history. `Workspace::edited` ignores the editor echoing the buffer's own text, so a reload doesn't mark the tab dirty.
- **Buffers:** the editor gets `\n` text; `Buffer` remembers CRLF and BOM and restores them on save (byte-identical round trip; tests in `core/src/buffer.rs`). Non-UTF-8 files open read-only and are never saved.
- **Text sizes** (the rem stays 16 px, so spacing is unchanged; hierarchy comes mostly from weight and color, not size):
  title 16 semibold = `text_base` (dialog titles — GPUI Kit's default — and the heading of a full-tab page like pi Settings) ·
  body 14 = `text_sm`, the default (the shell root and every dialog set it; don't size body text yourself) ·
  emphasis 14 semibold (group/section headers, item names) ·
  meta 12 = `text_xs`, usually `muted_foreground` (paths after names, counts, hashes, dates, hints, status bar; small-caps section labels are 12 semibold muted) ·
  code 13 = `mono_font_size` (editor), 12 mono for snippets inside panels.
  Content (a commit message, a chat reply) is body, never a heading. GPUI Kit's `ListItem` hard-codes 16 px: add `.text_sm()`. Chat markdown uses a flatter heading scale (`chat_text_style`).
- **Colors** (`pide_core::colors`, audit and full table in `docs/COLORS.md`): neutral by default; a hue always means something and the same thing in every panel.
  GPUI Kit's names lie: in the dark theme `theme.primary` and `theme.link` are white and `theme.accent` is border gray — never use them as colors or for selection.
  `Button::primary()` (white fill) only for the one main action of a view (Commit, a dialog's OK) · toggles/segmented/chips: `colors::toggle(b, on, cx)` · selected row `list_active`, hover `list_hover` ·
  accent blue `colors::accent` (checked checkbox, active tab marker, links, busy/starting) · file status `colors::change` (modified blue, added green, deleted gray, untracked/conflict red, JetBrains) ·
  `danger`/`warning`/`success` for problem states only, as text or dots, not fills · notice bars `colors::notice_bg` + body text · no red buttons on list rows (red = final confirm or Stop).
- **`taffy` must stay at 0.15.0** in `Cargo.lock` (GPUI's `profiler` feature needs it). After `cargo update`, run `cargo update -p taffy --precise 0.15.0`.

## Running and logs

```sh
cargo run -p pide -- <project-dir>        # debug (dependencies optimised; our crates fast to rebuild); no dir = last project
cargo run -p pide --release -- <dir>      # for performance checks
cargo test --workspace --locked
# frame-time check in the real app (window must be visible and frontmost; macOS throttles hidden windows):
XDG_STATE_HOME=/tmp/pide-bench PIDE_BENCH=$PWD/spike/fixtures/large.rs ./target/release/pide .
grep bench /tmp/pide-bench/pide/pide.log
```

- App log: `~/.local/state/pide/pide.log` (`RUST_LOG=debug` for more). UI stalls over 16 ms show up as `ui thread blocked` / `slow frame` warnings.
- pi: `~/.local/state/pide/pi-rpc.jsonl` (every raw line, both directions), `~/.local/state/pide/pi-stderr.log`.
- Layouts: `~/.local/state/pide/layouts/<hash of project root>.json`. Recent projects: `~/.local/state/pide/recent.json`. Keymap: `~/.config/pide/keymap.json`.
